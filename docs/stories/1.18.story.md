# Story 1.18 - Correcao da Sincronizacao Manual de Pagamentos do Gestor

## Status

Ready for Review

## Context

Um gestor reportou um falso negativo na conciliacao manual de pagamentos: a inscricao permanecia `payment_pending` no painel `/admin`, mas o comprovante do Mercado Pago mostrava a venda como aprovada. A investigacao mostrou que o botao manual do gestor consultava `GET /api/checkout/status` sempre por `registration_id`, enquanto a area do atleta ja priorizava `payment_id` quando ele estava persistido. A rota de status tambem dependia de uma reconciliacao fragil por busca de transacoes recentes e fallback por e-mail do pagador.

Esta story corrige o fluxo manual do gestor para alinhar o uso de `payment_id` ao caminho mais confiavel ja usado pela area do atleta, sem alterar contrato publico, schema ou webhooks.

## Acceptance Criteria

- [x] AC1: O botao manual `Sincronizar pagamento` no painel do gestor usa `payment_id` quando a inscricao possuir identificador real de pagamento e o metodo nao for `mercadopago_preference`.
- [x] AC2: O painel do gestor mantem `registration_id` como fallback para inscricoes sem `payment_id` utilizavel, incluindo fluxos `mercadopago_preference`.
- [x] AC3: `GET /api/checkout/status` passa a priorizar o `registration.payment_id` persistido quando recebe apenas `registration_id`, desde que o metodo nao seja `mercadopago_preference`.
- [x] AC4: A busca por pagamentos recentes no Mercado Pago permanece apenas como fallback para legados e `mercadopago_preference`.
- [x] AC5: Testes de regressao cobrem o fluxo manual do gestor, a preferencia por `payment_id` no backend e a preservacao do fallback seguro para `mercadopago_preference`.
- [x] AC6: `npm run lint`, `npm run typecheck` e `npm test` passam, e `npm run build` conclui com sucesso.

## Scope

### In

- Ajuste do handler de sincronizacao manual no painel `/admin`.
- Hardening da rota `GET /api/checkout/status`.
- Atualizacao da documentacao tecnica do incidente.
- Atualizacao de testes estaticos de regressao.

### Out

- Redesenho completo da conciliacao de pagamentos historicos.
- Mudancas de schema ou migration.
- Alteracoes no webhook do Mercado Pago.
- Mudancas no contrato publico da API.
