# Story 1.16 - Hardening de APIs Expostas e Checkout Publico

## Status

Ready for Review

## Context

A auditoria `docs/AUDITORIA-APIS-EXPOSTAS-2026-06-21.md` identificou exposicoes criticas na superficie publica do WODArena, incluindo takeover de conta de atleta no inicio da inscricao, uso indevido de `SUPABASE_SERVICE_ROLE_KEY` como fallback do segredo de sessao, checkout publico sem prova de posse da inscricao e tabelas/funcoes do Supabase com exposicao desnecessaria via REST/RPC. Esta story consolida a remediacao tecnica dessas falhas sem alterar o fluxo funcional principal do produto.

## Acceptance Criteria

- [x] AC1: O segredo de sessao deixa de reutilizar `SUPABASE_SERVICE_ROLE_KEY` e passa a usar um segredo dedicado.
- [x] AC2: `POST /api/registrations/start` nao sobrescreve a senha de atletas existentes sem validacao da credencial atual.
- [x] AC3: Rotas publicas de checkout, status e envio de comprovante exigem sessao valida ou token assinado de acesso a inscricao.
- [x] AC4: `GET /api/app/bootstrap` deixa de retornar PII desnecessaria para clientes anonimos, inclusive em `leaderboardEntries`.
- [x] AC5: O backend deixa de depender de `events.mp_access_token` para cobrancas do Mercado Pago.
- [x] AC6: Uma migration de hardening fecha exposicoes publicas desnecessarias no Supabase, incluindo RLS ausente e RPC publico.
- [x] AC7: Tipos, clientes e testes de regressao acompanham as mudancas de seguranca.

## Scope

### In

- Hardening de sessao server-side.
- Hardening de inicio de inscricao e checkout publico.
- Sanitizacao do bootstrap anonimo.
- Remocao do uso legado de `mp_access_token` em `events`.
- Migration de seguranca para RLS/policies/RPC.
- Atualizacao de testes estaticos de regressao.

### Out

- Migracao para Supabase Auth nativo.
- Redesenho completo da arquitetura de bootstrap.
- Novo modelo de papeis para `coach`.

## Change Log

- 2026-06-21: Story criada para remediar as exposicoes identificadas na auditoria de APIs, checkout publico e superficie Supabase.
- 2026-06-21: `WODA_SESSION_SECRET` passou a ser o segredo dedicado de sessao e o checkout publico ganhou token assinado de acesso por inscricao para Pix, cartao, preferencia, status e comprovante.
- 2026-06-21: `registrations/start` deixou de sobrescrever senha de atleta existente sem validacao, e o bootstrap publico passou a remover PII excedente de atletas e leaderboard.
- 2026-06-21: Migration de hardening fechou RLS ausente em tabelas sensiveis, removeu politicas REST publicas desnecessarias, restringiu a RPC `apply_coupon_usage` ao `service_role` e aposentou `events.mp_access_token`.
- 2026-06-21: Validacoes finais executadas com sucesso em `npm run typecheck` e `npm test`; `npm run lint` concluiu apenas com warnings legados fora do escopo desta story.
- 2026-06-22: `GET /api/app/bootstrap` passou a exigir sessao obrigatoria, o payload anonimo foi movido para `GET /api/app/bootstrap/public`, o `AppContext` ganhou fallback controlado para 401 e as regressões foram atualizadas e revalidadas (`npm run typecheck`, `npm test`, `npm run lint` com warnings legados).
- 2026-06-22: Corrigido loop infinito de render no bootstrap do cliente ao estabilizar o setter de `useLocalStorage`, eliminando o `Maximum update depth exceeded` que mantinha a tela presa em carregamento.
