## Context

A súmula grava cada toque no servidor em cerca de 1 s. Para o telão ler uma linha por raia em vez de reprocessar o log a cada segundo, o servidor resume o log a cada lote gravado.

Plano aprovado pelo usuário em 2026-10-19 (decisões D1 a D4) e 2026-10-20 (D5 a D9): [docs/PLANO-TELAO-LEADERBOARD-AO-VIVO.md](../PLANO-TELAO-LEADERBOARD-AO-VIVO.md). Desenho aprovado: [docs/design/telao-ao-vivo/](../design/telao-ao-vivo/README.md). A aprovação do usuário substitui a validação do @po, como nas Stories 1.43 a 1.52.

## User Story

**Como** público no evento,
**quero** ver as repetições de cada raia mudarem enquanto a bateria roda,
**para** acompanhar a disputa ao vivo.

## Acceptance Criteria

- [x] AC1: `appendSheetEvents` grava `scoresheets.live_progress` a cada lote: repetições, rounds, feito por segmento, segmento atual, fim (For Time), último registro, carga e tentativas (carga máxima) e início estimado do relógio da súmula (menor "gravado em − instante"). Calculado no servidor com `deriveSheetState`/`deriveMaxLoadState`; nada vem do aparelho.
- [x] AC2: Sem a coluna (migration pendente), o lote é gravado como antes, sem o resumo.
- [x] AC3: Súmula sem resumo gravado é calculada do log na leitura do telão.
- [x] AC4: Ordem parcial (`rankLiveEntries`): For Time por quem terminou (menor tempo), depois mais repetições, depois quem chegou antes ao último registro; AMRAP por repetições e chegada; carga máxima por carga, menos tentativas e chegada. Empate total divide a posição. Sem registro: sem posição, no fim, pela raia.
- [x] AC5: O parcial nunca é gravado em `scores`.
- [x] AC6: Testes e gate `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.
