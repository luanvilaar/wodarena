# Story 1.9 - Cronograma Publico Sem Duplicidade e Recuperacao de Senha

## Status

Ready for Review

## Context

Foram identificados dois problemas operacionais: a visualizacao publica do cronograma exibia baterias duplicadas quando o admin salvava baterias para workouts equivalentes, e o login de atletas/gestores nao possuia recuperacao de senha por e-mail.

## Acceptance Criteria

- [x] AC1: A pagina publica do evento nao exibe baterias de prova duplicadas com mesmo horario, numero, titulo e atletas/equipes.
- [x] AC2: A pagina publica do evento nao exibe baterias tecnicas ainda nao publicadas.
- [x] AC3: Atletas e gestores conseguem solicitar recuperacao de senha pelo login do `/admin`.
- [x] AC4: A recuperacao envia e-mail HTML com link temporario e de uso unico.
- [x] AC5: O link permite definir uma nova senha e invalida o token apos uso.
- [x] AC6: Quality gates (`npm run lint`, `npm run typecheck`, `npm test`, `npm run build`) passam.

## Tasks

- [x] Corrigir composicao publica do cronograma para deduplicar baterias equivalentes.
- [x] Criar persistencia server-side de tokens de recuperacao.
- [x] Criar endpoints de solicitacao e redefinicao de senha.
- [x] Criar template HTML de recuperacao via Resend.
- [x] Ligar fluxo de recuperacao e redefinicao na tela de login.
- [x] Adicionar testes de regressao.
- [x] Rodar quality gates.
