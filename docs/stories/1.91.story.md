## Context

Com muitas provas ligadas a categorias diferentes, a lista "Provas WODs Cadastradas" da aba Provas virava uma fila de cartões quase iguais, com a categoria no menor texto do cartão. A lista passa a agrupar pela prova do evento (a N-ésima prova de cada categoria, a mesma numeração do construtor de baterias), com uma linha por categoria, descrição recolhida e as lacunas visíveis.

Fonte: [docs/design/provas-cadastradas/README.md](../design/provas-cadastradas/README.md) (opção B, decisões D1 a D6). Tamanho: **M**. Só frontend: sem banco, migration, API, autenticação ou infraestrutura.

**Dependências:** Story 1.87 (`getDivisionWorkoutsInOrder`).

## Acceptance Criteria

- [x] AC1: A lista é agrupada pela prova do evento: um título por prova ("PROVA 1"), com o código repetido aparecendo uma vez, e uma linha por categoria, com "N de M categorias" (verde quando completa).
- [x] AC2: Nome igual ao código aparece uma vez; nome ou código diferentes entre categorias aparecem só na linha de cada uma.
- [x] AC3: A descrição dos movimentos fica recolhida e abre por linha (botão com `aria-expanded`); desempate, prazo de submissão (Qualifier) e súmula digital continuam visíveis na linha.
- [x] AC4: Editar e Excluir dizem a prova e a categoria no `aria-label` ("Editar prova PROVA 1 · Dupla Rx Masculino").
- [x] AC5: O que falta cadastrar aparece no fim da seção; "cadastrar" só preenche o formulário (categoria e código) e leva o foco ao nome, sem gravar. Só a primeira prova que falta de uma categoria tem o atalho; as outras dizem qual cadastrar antes.
- [x] AC6: Prova "Geral" vale para todas as categorias e aparece como uma linha ("Todas as categorias"); onde não cobre todas, "Geral · N categorias" com os nomes.
- [x] AC7: Prova que nenhuma categoria enxerga aparece em "Sem categoria ativa", editável.
- [x] AC8: Editar, Excluir, formulário, ordem das provas e o estado vazio ("Nenhuma prova cadastrada neste evento.") seguem como antes.
